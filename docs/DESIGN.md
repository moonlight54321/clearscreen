# 清屏 · 设计文档（DESIGN.md）

## 0. 需求溯源

原始需求（安卓版）：
1. 拦截其他 App 的开屏广告与误触跳转
2. 按 App 统计拦截次数
3. 开机自启、后台保活

**iOS 平台裁决**（为什么不能照搬）：
| 安卓手段 | iOS 对应物 | 裁决 |
|---|---|---|
| 无障碍服务读屏+自动点"跳过" | 无跨 App 读屏/触摸 API | 物理不存在 |
| 悬浮窗防误触 | 无跨 App 悬浮窗 | 物理不存在 |
| 后台保活常驻 | 无常驻服务 | 物理不存在 |
| 拦截流量 | NetworkExtension 隧道 | **唯一正门** |

所以 iOS 版语义翻译为：**DNS 断粮式拦截 + 域名级统计**（AdGuard/AdLock 同赛道）。

## 1. 拦截原理（三层断粮）

```
App 请求 ad.toutiao.com
  → 系统 DNS 指到虚拟解析器 198.18.0.2（隧道内）
  → 扩展解析报文拿到域名
  → 命中拦截清单（后缀匹配）
  → 立刻回 NXDOMAIN（"此域名不存在"）
  → 广告 SDK 拿不到素材 → 开屏位不加载
```

- **断粮 vs 打死**：不去拦"已下载的广告画面"，而是让广告根本下载不下来
- 未命中域名：原查询转发到真实上游（阿里/DNSPod），答案原路送回
- 劫持公共 DNS（8.8.8.8 等 /32 路由进隧道）防 App 硬编码绕过

## 2. 数据面

```
packetFlow.readPackets ─→ IPv4/UDP/53 解析 ─→ DNSMessage（40行解析器）
     │                                        │
     │                            命中：NXDOMAIN 应答（手工造 IP+UDP 头）
     │                            未命中：NWConnection → 上游 :53
     ↓                                        │
StatsWriter（2s 节流）─→ App Group UserDefaults ─→ Darwin 通知 ─→ 主 App UI
```

- 轻量模式：只有 DNS 进隧道，正常流量零经过——无延迟无电耗
- 统计容量自管理：日榜 30 天 / 域名榜 500 条自动裁剪
- 隐私：DNS 记录只写本机沙盒，全工程零上传代码（可审计）

## 3. 风险工程（自保位）

1. **总闸（masterOn）**：任意时刻一键"全部直通"——规则崩了先救网再修
2. **上游自动重连**：NWConnection failed → 重开
3. **并发上限 64 + 8 秒超时**：表不泄漏、不雪崩
4. **回环保护**：当前选中的上游 DNS 永远不进劫持名单
5. **审计通道**：README 附行号级审计指南（验证"没有偷偷联网/上传"的两条 grep 路线）

## 4. 与安卓版的对照（功能矩阵）

| 原需求 | iOS 版实现 | 打折程度 |
|---|---|---|
| 开屏广告拦截 | DNS 断粮（大部分命中） | 预缓存广告杀不掉 |
| 误触跳转防护 | 间接削弱（跳转域名多为广告联盟，一并断粮） | 不能盖膜 |
| 按 App 统计 | 按域名统计（部分可人工推断归属） | 隐私墙限制 |
| 开机自启 | iOS 拓扑：VPN 配置常驻，重启后一键重连 | 系统不让全自动 |
| 后台保活 | 隧道由系统托管，不占后台配额 | 等价 |
